# B033 — Fusion UI and preview

Added the mobile Fusion tab with owned-card pagination/filtering, explicit five-source selection, server preview, separate loss acknowledgement and confirmation, definitive rejection recovery, exact-receipt verification and recorded child/parent lineage. Selection and preview never call confirmation. The review discloses every source UUID/version/level, child UUID/template/series/branch/rarity/level, expiry/policy and loadout/manager/favorite effects. Double taps are guarded immediately. Sources remain in archive/history after consumption.

Ambiguous transport or invalid-response failures retain the same preview and command ID, block refresh/new selection/cancel and offer the same confirmation retry. A late original receipt cannot be accepted for a different preview. The Fusion component stays mounted across tab navigation; account/session changes reset the workspace and abort pending requests. A full application restart requires collection/archive reconciliation; no native durable pending-intent store is claimed. Definitive server rejections require refresh and a fresh preview. The client verifies the complete child, exact five parents, effects and preview identity before displaying success. It computes no reward or authoritative eligibility.

The new-card reveal starts fully visible, uses a short opacity animation only after the OS reports reduced motion disabled, responds to preference changes and stops on unmount. Failure to read the preference leaves a static visible result. Text always identifies the result and lineage; animation is never required to finish the flow. No animation or network dependency added. Policy defaults remain disabled; preview mode does not grant owned cards.
