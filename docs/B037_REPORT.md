# B037 — Missions and seasons

Extended the durable achievement goal/consumption/grant engine with published daily, weekly and bounded-season windows. Definitions are immutable and versioned; timed goals require explicit start/end, UTC daily boundaries and Monday UTC week starts. Start is inclusive/end exclusive. Progress uses the original server-result occurrence time, never worker arrival time. Season goals share this same exact-once prestige reward path; no unreviewed currency/card/XP reward amount is selected.

The worker projects newly ingested facts and recovers existing eligible facts after restart. Backfill requires matching frozen permanent-account/opponent/command eligibility, skips outside-publication events and already-completed windows, and serializes on the user before consuming an event. Independent workers cannot reissue a window reward. SQL computes the same window and rejects a forged window. The owner-only mission API includes configured current missions, progress and completion even before the first event; history remains in progression records. No daily timer resets/deletes counters or reopens grants.

Files: progression contracts, pure window function/tests/export, progression service/controller/worker, historical-time private result fixture, mission integration cases, SQL migration/owned reversal `202610300009_mission_windows`; decisions/status/report. No new external dependency or schema model.
