# B049 security engineering audit

Scope: managed JWT issuer/audience/algorithm/expiry/session checks; HTTP and socket authorization; recipient-safe poker/Spades projections; strict schemas, payload/rate bounds and safe errors; scoped MFA administration and dispute inspection; original asset publication; fusion/inventory/RNG/idempotency and journals; verified cosmetic billing/restore/refund; tracked credentials and dependency supply chain. This is an engineering review plus regression evidence, not an independent penetration test or legal/store certification.

## Findings and remediation

- Tournament operations retained legacy coarse ADMIN authority after scoped roles were added. Require current GAME_OPERATOR scope for scheduling/replay; database audit writes also verify that grant. Existing operators must be explicitly provisioned; no public grant API exists. Tests deny unscoped administrators and low-assurance sessions, and retain current-role revocation checks.
- A disabled offer could reject a legitimate delayed first platform proof. Separate sale visibility from fulfillment: the storefront hides disabled offers, while an approved fixed SKU's valid bound platform proof still fulfills exactly once. Existing restore/refund evidence remains valid. Main still cannot initiate a payment. This changes no cosmetic contents, prices, currencies or earned power.
- Sensitive JSON responses lacked explicit cache/frame/sniffing controls. API now sends no-store, nosniff, no-referrer and deny-all document/frame CSP, and omits X-Powered-By. TLS/HSTS belongs at the reviewed deployment edge; loopback development does not impersonate TLS.
- Add a deterministic tracked-secret/backup gate to CI. Detect actual private-key headers, provider token patterns and credential/backup paths; allow public templates and CA certificates. It scans tracked source, not ignored local secrets, and prints only flagged paths. This complements review rather than proving every possible secret is absent.
- Current registry advisories identified minimatch and glob in CLI/lint dependency paths. Maintainer fixes are version-scoped to the exact affected 10.2.6/13.0.6 packages across installed lint/Expo transitive paths; root lint and real Expo exports validate those paths. Node requirements support the pinned Node 22 runtime. Sources: [maintainer minimatch advisory](https://github.com/advisories/GHSA-g3hv-75wg-m249) and [maintainer glob advisory](https://github.com/advisories/GHSA-3g3m-2fjr-6pw4). No advisory text was treated as executable instruction.

## Threat boundaries and evidence

Clients cannot upload wins, balances, grants, shuffle state or trusted steps. JWT key URLs come only from server configuration. Socket credentials are bounded handshake auth, never URL query credentials; reauthentication precedes commands and private refresh. Existing room tests cover foreign readers, hidden-card payloads, reconnect/stale versions and token revocation. Financial/inventory tests retain concurrency, immutable provenance, balanced ledgers and exact source-key replay. New checks cover current game-operator scope, cache/error/request-size boundaries, secret detection and delayed verified proof fulfillment.

Review database credentials separately: SQL constraints protect normal application integrity, not a privileged DBA who can change schema/triggers. Capability provisioning and secret rotation remain operator tasks. No checkout, billing provider, health reward source or tournament/economy policy was activated during this audit.

Remaining gates: independent adversarial review on actual staging; managed-provider MFA/link/device acceptance; real Apple/Google positive sandbox and webhook tests; native platform security/permissions; key rotation/backup access, deletion/retention and deployment edge configuration. The inherited low deepmerge advisory has no published patched version in the observed feed; its path is Expo configuration tooling with trusted project config, not player-request processing. Treat untrusted repository configuration as executable/untrusted and keep CI credentials read-only/absent. Record future findings and refuse beta if a critical/high issue is known and unmitigated.

Rollback: remove optional headers/gate or revert scoped dependency changes only after evaluating regressions; do not restore coarse administrator authority or reject legitimate paid proofs. The new game-scope rollback is owned disposable DB only; production repair retains access/audit/payment evidence. No production mutation was executed.
