# B048 accessibility audit

Automated/source audit scope: gallery/card inspection, Classic/Spades legal controls, fusion confirmation, activity permission and separate nonwalking quests, storefront/history and tournament status/reporting. This is an engineering audit, not a claim of WCAG certification or physical-device acceptance.

Observed existing protections: full canonical rank/suit names and distinct suit shapes, visible text alongside red/black ink, explicit rarity/level/branch text, min-48 controls, scalable Text, scrollable detail/confirmation flows, native modal close handling, labeled inputs, live status/reconnect notices, exact server-driven legal controls, nonwalking path that requires no health/GPS permission, no default sound/haptic cue and no color-only win/eligibility state.

Fixes: share a conservative reduced-motion preference through the session provider instead of subscribing per card; suppress card modal fade when motion reduction is enabled; retain press handling during modest motor drift. OS preference lookup failure defaults to reduced motion. Rank/suit semantics and the original hashed art remain unchanged.

Automated evidence: standard sRGB luminance anchor checks; active text/muted/accent combinations, selected buttons and both card inks require at least 4.5:1 against their actual surfaces. Every one of 52 faces has a full accessible rank/suit label in the rendered tile. Source controls retain min-height 48, and renderer checks verify their explicit label/disabled state; the default motion preference is conservative. Existing fusion acknowledgements, legal/disabled game controls, reconnect, accessible quest and tournament tests remain part of quality validation.

Manual acceptance matrix still required on current supported iOS/Android devices: VoiceOver/TalkBack swipe order and announcements; card modal focus entry/return and Escape/back; 200% text and largest OS text without clipping; 320-point width/landscape/tablet layouts; switch/keyboard navigation; one-handed motor control; color vision simulation; reduced-motion changes mid-animation; sound/vibration unavailable/muted; health denial/revocation and full nonwalking reward path; all core end-to-end journeys with real managed identity. No physical device or native compiler evidence exists in this run. Xcode/Android toolchain gaps remain documented in B034/B047.

Open dependency acceptance: accessible proof still awaits B068/B069 Press consumption; real store/native flows and expanded gameplay activation remain gated. Product/support must validate wording and alternative tasks. No accessibility claim overrides server rules or grants a reward. Rollback reverts these optional UI fixes without changing persisted state. Next: B049 security audit.
