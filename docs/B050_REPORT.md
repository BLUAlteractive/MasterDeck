# B050 — Load and failure evidence

Added an owned 500-room/1,000-distinct-user WebSocket harness, bounded server handshake-policy configuration, transactional cancellation/retry and lost-acknowledgement recovery. Main retains its 60-handshake/IP/minute and packet limits; only the isolated fixture bootstrap raises the handshake allowance to measure capacity without a 17-minute anti-abuse ramp. Signed users are provisioned before measurement through the real identity service; room clients still perform actual JWT verification, private resume and legal commands. No caller DATABASE_URL, developer data or production service is used.

Observed two loopback runs on Node 22.22.0, macOS arm64, 12 reported CPUs: 500 simultaneous private rooms, 1,000 connected distinct fixture users, 500 completed hands per run and zero private-card failures. These unfunded reducer/transport fixtures do not measure 500 funded production tables, distributed hosts, mobile networks, sustained soak or real device behavior. Actual funded ledger/lock concurrency remains covered separately by the integration suite.

The first run found a genuine adapter-wrapped serialization conflict not handled by identity retries. Added bounded recognition of only known PostgreSQL transaction conflicts plus modest retry backoff; auth/provider failures never retry indiscriminately. Account provisioning is excluded from the measured room workload. A controlled cancellation of this owned transaction's backend query proves no partial credit survives; retrying its source ten times credits once.
