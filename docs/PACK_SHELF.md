# Pack shelf, reveals and recovery

Choose **Pack shelf** in the connected local app. The two pathways show earned Trail Credit prices with exact rational per-draw odds, or known presentation-only cosmetic contents with a reference price. Current time/stock/region metadata is visible. Guests must link before spending; preview creates no balance or reward. Native paid checkout is explicitly unavailable in this build. Verified cosmetic history remains separate from earned opening history.

An earned open saves its UUID and expected offer hash before sending. Saved state is scoped to the authenticated owner and API origin, using browser tab session storage or the existing encrypted native store. Storage failure blocks sending. No token, seed or balance is stored in that intent. Reopening the screen recovers the same command even when the current catalog is unavailable. A lost reply keeps other openings disabled until recovery/resolution; it never generates a new key for retry. Confirmed receipts display complete text outcomes and owned IDs immediately, with optional reduced-motion-aware fade only. Inventory is reloaded and balances/supplies are refreshed from the server.

**Cancel saved attempt or recover its receipt** resolves a pending command under the server user lock. If an opening already committed, return its original safe receipt. Otherwise persist an immutable `OperationRecord` cancellation fence keyed by owner/command. The open transaction checks that fence before spending, including when an earlier request is still awaiting an external region check. Cancellation never refunds or deletes committed rewards. Repeats are hash-bound/idempotent. Keep the saved intent if resolution or local cleanup fails. Deletion attempts to clear the owner's local pending entry together with credentials; failures use the existing explicit cleanup state.

`GET /v1/packs/openings?limit=20&cursor=...` is owner-scoped, bounded at 50 and returns safe receipt snapshots/time, with no RNG boxes, indices, seeds or other owners' cursors. `POST /v1/packs/cancel` accepts the strict saved `{packId, command}` shape. New opening requests accept no client-selected draw, price, currency or reward. The shared client verifies that the returned receipt matches the requested pack/hash.

Existing append-only `OperationRecord` storage suffices; no schema migration is needed. Roll back a deployment by disabling new admission/UI and retaining receipts and cancellation fences; never erase a fence while a delayed request may still arrive. Aggregate API latency/error and pack-open signals support monitoring without proof/user-specific logs. Database tests race cancellation against opening and reconcile the actual debit. Storage/transport and static accessibility tests do not prove physical-device screen-reader, reduced-motion, secure storage, platform checkout or network behavior; those gates remain open.
