# Versioned pack catalog

Public `GET /v1/packs/catalog?platform=APPLE|GOOGLE` returns only currently published, time-available definitions in the reviewed server allow-list. Main supplies none. Earned Discovery Packs disclose integer-weight per-draw odds as exact numerator/denominator fractions, draw count, ALLOW_COPIES duplicate policy, NONE guarantee, Trail Credit price, whole-opening stock cap, dates and region eligibility metadata. No per-item stock adjustment, guarantee or paid random mechanic is silently introduced. Region verification and atomic stock consumption belong to B063; the catalog itself grants nothing.

Fixed paid packs currently require unlimited stock (`stockLimit: null`); finite paid-stock promises require a separately verified platform reservation/admission design and cannot strand valid delayed receipts. Earned pack stock caps are enforced by B063. Fixed Cosmetic Packs reference the existing approved fixed product and exact original cosmetic contents for both platforms. No card template, earned rarity/level/style family, press speed, earning rate or functional entitlement can appear in a fixed paid definition. Store reference prices are not live native billing quotes. Real platform checkout/territory/restore acceptance remains gated by B064 and provider/device configuration. Disabled offers are hidden; already-paid proofs must continue authoritative reconciliation.

`POST /v1/packs/admin` requires current permanent ADMIN, MFA, explicit scope, reason and stable command ID. CONTENT_EDITOR may DRAFT a new immutable slug/version/definition; no card is minted. Two distinct CONTENT_REVIEWER actors submit CONTENT and ECONOMY review of the exact definition hash and inspect external approval evidence. A separate CONTENT_PUBLISHER actor may publish after both, then retire without rewriting history. Creator/reviewers/publisher must be distinct. Revalidate commercial original art manifests and fixed product contents before review/publication and each new use. A trusted reference is not a real owner/economy/legal approval; actual activation still needs reviewed server configuration and signed launch gates.

SQL preserves definitions, reviews and audit evidence, validates versioned state transitions and publication separation. Published weights/prices/contents cannot be edited in place; introduce a new ID/version and review it. Catalog retirement must not delete existing openings or entitlements. Reverse SQL is only for owned disposable tests; production rollback deactivates the allow-list/affected offers and retains version/audit history. Catalog failures expose fixed error codes, not private operator data.
