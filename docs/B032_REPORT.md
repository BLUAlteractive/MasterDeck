# B032 — Fusion transaction

Added a pure five-copy recipe, strict authenticated preview/confirmation/lineage APIs, immutable previews/jobs/parent edges and atomic inventory provenance. Preview allocates a proposed child UUID but changes no inventory. Confirmation locks the active account/session then source UUIDs in order, rechecks the reviewed policy, five-minute DB-time expiry, source versions and previewed selection effects, consumes exactly five sources, creates the exact new child, records lineage and updates selections in one transaction. No source row/history is deleted. Same-key retries and new-key confirmation of a completed preview return the original receipt, including after policy disablement. Overlapping previews cannot both consume sources.

The configurable recipe preserves matching earned template/style and rarity, original series/face and branch; blue 1→3→5 and red 2→4→6. Locked, consumed, revoked, mismatched and capped-edition sources are rejected. Capped-edition supply/serial handling and production rarity policy remain open. Main supplies no fusion policy; the fixture approval reference is test-only. This implements configuration infrastructure without selecting an unapproved economy default. Printing Press remains a separate in-place transition.

Preview discloses loadout replacement, affected manager slots and favorite inheritance. Confirmation replaces an affected loadout face with the child, keeps 52 references and advances its revision; consolidates affected manager slots into the lowest affected slot and advances its revision; inherits a favorite if any source was favorited. Concurrent selection/preference changes require a new preview. Unaffected selections are unchanged; parents retain historical favorites.
