# Fixed cosmetic packs

A published fixed pack references one immutable published cosmetic product. Both platform SKUs resolve the exact same item set, with one to twenty presentation-only items. Independently reviewed pack publication binds this reference to the definition hash. Functional fields and paid randomness are structurally unavailable; finite paid stock is disabled until trusted purchase reservation exists.

An authenticated permanent owner can resolve `GET /v1/packs/:id/fixed-offer?platform=APPLE&expectedDefinitionHash=...` (or GOOGLE). It requires configured platform verification, current reviewed allow-lists, unchanged offer hash, a live global offer and enabled product. Regional purchase admission remains unavailable until reviewed region verification exists. The safe response identifies the exact SKU and fixed contents. This route grants nothing and is not a price confirmation or payment receipt. Obtain the actual localized price/confirmation and proof from native platform billing, bind it using `/v1/billing/context`, and submit only the strict signed transaction/purchase token to `/v1/billing/verify`.

Existing B039/B040 verification grants every snapshotted item in one transaction, keyed by platform/environment/transaction and account binding. Retries create no duplicate entitlements. Verified refund/revocation revokes all grants from that purchase while preserving unrelated entitlements and immutable history. A stale active restore never resurrects a revoked purchase. Restore/current purchase and owner purchase history report the original complete snapshot. Google acknowledgement follows commit and retries independently.

Sale admission is distinct from fulfillment: disabling or retiring an offer does not invalidate an already-paid verified SKU. Keep historical approved product bindings available to delayed verification/refund/restore. Never require a currently visible pack to process legitimate prior proof.

No new persisted billing journal or migration is needed. Existing migration/rollback/recovery protections apply; production repairs retain purchase/grant/event evidence. Observe aggregate billing verification/reconciliation signals without printing proofs, tokens or user IDs. Tests use clearly isolated provider fixtures, not real platform purchases. Main has no live billing approval/provider; the app's native checkout remains unavailable until a genuine host billing bridge, platform products and real-device purchase/refund/restore evidence exist. Do not substitute browser success or fixture proof for payment.
