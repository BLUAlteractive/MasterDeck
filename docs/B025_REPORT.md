# B025 — Separate poker modes

Added immutable lobby mode/ruleset pairs and separate public queue selection by both fields. Private invitees inherit the host's fixed mode. Classic uses `CLASSIC_NLHE_V1`; Evolved lobbies use `EVOLVED_A_EXPERIMENTAL_V1` and explicitly report balancing-review admission denial. SQL rejects mismatched pairs, changing a lobby's selected mode/version and any Evolved STARTED state. Funded admission independently requires Classic's exact version. Existing private room and authorization/rate limits remain in force.

Changed files: lobby/chip contracts; Prisma Lobby metadata, queue index, `202610300004_poker_modes` migration and matching owned-test rollback; API lobby/settlement services and six mode integration cases; pure explicit mode dispatcher/tests; mobile CollectionApp navigation, authenticated collection client, PlayLobby, PokerMatchScreen and semantic/transport tests; decisions, status and this report.

The Play tab exposes labeled modes, public/private joins, ready/unready/leave, refresh, private creation receipt and configured Classic start. It uses the existing refresh-aware bearer getter, aborts old requests, retains command IDs on ambiguous retries and rejects changed actions until refresh/retry. Current game projections are keyed by game ID, preventing stale views from appearing under another mode. The read-only match display labels the exact rules and only renders server-projected visible cards. Full betting controls and real device/reconnect UX acceptance are not claimed by this mode-selection ticket.

Also fixed a relevant existing omission: lobby reads now include stored status, instead of defaulting started lobbies to OPEN. They include a member-authorized current game ID for the labeled display. Legacy no-mode command hashes are unchanged (mode is optional at parsing, resolved server-side), and old Classic receipts receive compatible schema defaults. Clients cannot choose rules versions, scoring metadata or a join-time mode override.

Tests prove Classic never invokes the Evolved evaluator even with extra forged metadata, reject cross-mode versions, verify concurrent queue isolation/private inheritance and SQL guards, keep ready/funded Evolved players out of Classic admission without locking inventory/debiting chips, preserve legacy retries and display actual started-Classic status. An initial DB test incorrectly assumed two new Classic joins must share one table even with an earlier auth fixture's open seat; corrected the assumption while retaining mode-isolation checks and added per-case cleanup. No production matching behavior was weakened.
