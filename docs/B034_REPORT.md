# B034 — Health steps bridge

Added a local Expo module with read-only HealthKit and Health Connect adapters, optional permission actions, a foreground-only Activity screen and strict bounded source/revision records. Exact duplicate records are collapsed for local review; conflicting revisions, overlapping sources, manual entries and implausible rates are excluded. No native payload is treated as a trusted server proof, submitted for reward or converted into a fabricated step sample. B061 owns canonical cross-session/device ingestion and correction accounting. No GPS, background collection or health writes are requested.

Files: mobile local module config/package, iOS podspec/Swift implementation, Android manifest/Gradle/Kotlin implementation and rationale activity; `apps/mobile/src/activity/{Activity.tsx,bridge.ts,bridge.test.ts,native.ts}`, mobile app.json/navigation; activity contracts/export; decisions/status/report. Health Connect is pinned to stable 1.1.0. Expo's existing native module APIs are reused; no JS dependency/version change.

Validation: `pnpm ci:quality` passed 267 tests in 43 files, lint/format/strict types and 11 builds including web export (`/tmp/deckforge-b034-quality2.log`). Five cases cover foreground/denial/unavailable paths, bounds/schema rejection, overlapping/manual/rate/revision checks and late background completions. `xcrun swiftc -frontend -parse` passed Swift syntax. Expo autolinking resolve passed for Apple and Android and discovered DeckForgeHealth. Formatting initially required a second pass; corrected. No DB change; previous 109 database cases twice remain applicable.

Acceptance remains partial: this machine has Xcode 26.3 versus the repository's 26.4+ requirement, no adb/Android toolchain and no connected physical-device evidence. Native compilation, entitlement/signing provisioning, Android permission activity lifecycle and two-platform grant/denial/revoke/reimport tests remain required. Do not mark the ticket's physical-device acceptance complete. HealthKit intentionally does not reveal read denial, so READ_REQUESTED and empty records never claim GRANTED. Health Connect denial remains explicit. No permission is requested automatically. The screen offers the separate nonwalking path; B035/B037 supply that flow.

Rollback reverts this optional native adapter and rebuilds development clients; no persisted data rollback. No health record logging/storage is introduced. App-store health declarations and privacy review are launch gates.
