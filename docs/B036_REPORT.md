# B036 — Server-derived achievement engine

Added immutable verified-result sources/events, versioned goal definitions, counter/consumption reconciliation and unique prestige-badge grants. Poker facts require an existing settled result, full private replay and matching server pot allocation; Spades facts require replayed completed result/winner; fusion requires the confirmed five-parent job. Source timestamps come from immutable server results, not arrival time. No client endpoint accepts achievement events, amounts or winners. No currencies, cards or XP amounts are issued by this badge-only implementation.

An explicit reviewed policy selects goals and permanent-account/opponent/player-command eligibility. Main supplies none by default. Immutable source processing preserves the selected eligibility evidence; policy changes cannot retune existing goals or reissue historical awards. Polling uses anti-joins against persisted processed sources, handles all three source families, retries safely and drains on shutdown. Goals saturate at their target; source/event/goal consumption uniqueness and deferred SQL checks prevent double progress or mismatched grants. Counters cannot be deleted or decreased. Public projection contains only the requesting user's counts and badges, never hands/opponent IDs.
